ValioValue MCP under the hood

What the purchasing agent can call, what each call does, and which Valio Aimo API sits behind it. State of branch feat/mcp-server-backend, 14 Nov 2026.

The big picture

Two sides. The buyer side runs the AI agent. The Valio side decides what the agent may see and do.

The four tools

The grey box is the exact description Haiku reads before deciding. * marks required inputs.

search_productsFind candidate products. No prices yet.
Description Haiku reads
Search Valio Aimo's static product catalog. Returns candidate products with labels, allergens, historic delivery reliability and category CO2 estimate. No prices here: use check_offer.
Inputs
NameTypeMeaning
query*textWhat the buyer needs, English or Finnish
filters.lactose_freeyes/noOnly lactose-free products
filters.exclude_allergenslistDrop products containing these, e.g. gluten
filters.categorytextValio category code
filters.country_of_origintexte.g. fi
limit1 to 25How many results, default 10
Calls
products.jsondelivery_reliability.csvcarbon_footprint.csvno Valio API call
How it works
  1. Translates the query into Finnish and Swedish too (milk → maito, mjölk).
  2. Ranks by name match plus a category signal learned from the catalog, so "milk" finds real milk first.
  3. Ignores negations like "milk free" and pushes down chocolate milk, coffee drinks and quark unless asked for.
Returns

Product id, name, brand, category, sales unit, lactose-free flag, allergens, labels, delivery reliability, CO₂ per kg.

check_offerGet live prices and stock for a shortlist. Creates fixed-price quotes.
Description Haiku reads
Get binding quotes: live price and availability from Valio Aimo for each product on the date. Each offer has a quote_id that fixes the price until quote_expires_at. Offers are sorted best first.
Inputs
NameTypeMeaning
product_ids*list, 1 to 25Ids from search_products
requested_date*YYYY-MM-DDDesired delivery date
quantity*numberAmount the buyer needs
quantity_unitL, KG, SALES_UNITLitres and kilos are converted per product
Calls
POST /api/pricePOST /api/availabilitySQLite: saves quotes
How it works
  1. One price request and one availability request for the whole shortlist.
  2. Litres per pack = price per pack ÷ price per litre. 1,000 L of 5 L cases becomes 200 cases, rounded up to whole packs.
  3. Can deliver only if not blocked, enough stock, on time and before the order cut-off.
  4. Sorts by can-deliver, then total price, then reliability. Top three get best, better, good.
  5. Each offer becomes a quote, valid until the cut-off or 30 minutes, whichever is first.
Returns

Per product: quantity in packs, price per pack and per litre, total, delivery date, stock, cut-off, reliability, CO₂, reasons it cannot deliver, quote_id. Plus the recommended product.

place_orderCommit to one quote. Valio's rules decide the outcome.
Description Haiku reads
Commit to a quote. Valio Aimo enforces the buyer's mandate (spend limit, availability, quote validity). Returns status 'confirmed', 'pending_approval' (wait for a human, you cannot approve) or 'rejected'.
Inputs
NameTypeMeaning
quote_id*textFrom check_offer
reason*textWhy this offer. Shown to the approver and in the audit log
Calls
SQLite: quote, orderPolicy engineno Valio API call
How it works
  1. Looks up the quote, so the price is exactly what check_offer returned.
  2. Runs the four policy rules below for the buyer.
  3. All pass: order confirmed. A soft rule fails: an approval request is created. A hard rule fails: rejected.

The mock API has no order endpoint, so orders live in our database.

Returns

Status, order id, every rule with pass or fail and why, total, delivery date, and the approval request if one was created.

The rules place_order checks

Enforced on the Valio side for every order. The agent cannot skip them, whatever its prompt says.

RuleChecksIf it fails
Quote still validThe quote has not expiredrejected
Ordered before the cut-offValio's closingTime for that delivery date is still aheadrejected
Full quantity on timeEnough stock, delivery on or before the requested date, not sales-blockedhuman approval
Spend limitNet total ≤ the buyer's limit in policies.json, currently 500 EURhuman approval

Human-only endpoints

Plain web endpoints on the MCP server, protected by a token. The backend calls them when you click Approve or open the audit trail. They are not in Haiku's tool list.

EndpointDoes
GET /internal/approvalsLists approval requests, filter by pending, approved or rejected
POST /internal/approvals/{id}Approve or reject. Approved orders are confirmed if the quote is still valid
GET /internal/orders/{id}One order
GET /internal/orders/{id}/auditEvery step for that order: agent, Valio, policy engine, human

How Valio knows who is calling: the backend sends X-Buyer-Id (which mandate applies) and X-Agent-Session (groups the audit log) with every tool call.
